# Handoff: finish verification and ship

Paste the prompt below into Claude Code, running on any account, from an empty folder. It needs nothing from the original machine.

```
Clone https://github.com/HEMANTH-A-7/composio-app-research and cd into it. Read README.md and HANDOFF.md first.

Context: this is a pipeline that researched 100 apps for Composio toolkit buildability.
- data/*.jsonl hold cached per-app results for each stage. baseline, scout and ground are complete (100/100).
- verify (the adversarial second-agent pass) reached only 8/100 because the original account ran out of usage.
- The live page is site/index.html. It is generated by `python agent/run.py export` from site/template.html + site/content.json + data/. Never hand-edit index.html.

Prerequisites: Python 3.10+, the `claude` CLI logged in on this machine (run `claude -p "say ok"` to confirm), and `pip install playwright && python -m playwright install chromium` for the screenshot check. No API keys are needed.

Steps:
1. Finish verification. The stage is cached and resumable:
     BUDGET_USD=40 python agent/run.py verify --workers 6
   BUDGET_USD caps total list-price spend across all stages, and about $27 is already recorded in the jsonl files. So to spend about $20 more, pass BUDGET_USD=47. If it stops on a usage/session limit, rerun the same command later; finished apps are skipped.
2. Rebuild:
     python agent/run.py review && python agent/run.py score && python agent/run.py export
3. Update copy that assumed a partial run, then rerun `python agent/run.py export`:
   - site/content.json, "honest" list: rewrite the item "The verifier only reached 8 apps" with the real count and the new verify accuracy from data/score.json.
   - site/template.html, hero sentence (search "passed automated verification"): if verify now covers all 100, say "All 100 rows verified by a second agent" and keep the automated-check clause.
   - site/template.html, ladder text (search "Reached ${nV} of ${nG}"): make sure it still reads correctly.
4. Secret hygiene: docs pages sometimes contain sample tokens. The pipeline redacts them on write, but run this before committing:
     python -c "import re,glob;T=re.compile(r'[A-Za-z0-9_-]{20,}\.[A-Za-z0-9_-]{6}\.[A-Za-z0-9_-]{20,}');[open(f,'w').write(T.sub('[redacted-example-token]',open(f).read())) for f in glob.glob('data/*.json*')+['site/index.html','site/data.json','site/findings.csv']]"
5. QA: serve site/ (python -m http.server 8765 -d site) and use Playwright to screenshot at 1440px and 390px. Check for no page errors, document.documentElement.scrollWidth == viewport width, and hero dots that do not move when hovered.
6. Ship:
   - If you have push access to the repo: commit (no Co-Authored-By line) and `git push origin HEAD:main`.
   - If not: fork it, push to the fork, and open a PR to HEMANTH-A-7/composio-app-research.
   - Deploy: `cd site && vercel deploy --prod --yes`. With the original owner's Vercel login, this updates https://toolkit-triage.vercel.app. On another account it creates a new URL; report it.
7. Report back: the new accuracy for each pass (baseline, scout, lint, scout_on_verified, verify from data/score.json), how many apps are verified, and which rows are still in data/review_queue.json.
```

## Notes for whoever runs this

- `data/gold.json` is the 25-app answer key. It is frozen: do not edit it to match agent output. If you believe a gold value is wrong, say so in the report instead.
- `data/human_overrides.json` holds manual corrections. They are applied to the published data but excluded from accuracy scoring.
- Verify runs gold-sample apps first, then the riskiest rows (low confidence, failed grounding).
